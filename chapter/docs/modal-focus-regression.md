# 模态关闭后的键盘焦点修复

## 已有运行证据与定位

主集成任务在真实 candidate4 观察到：鼠标点击“跳过已读”后，D/K/O/Esc 均不响应，角色站在原地受击；重试后再次点跳过，额外点击场景背景，D 立即恢复移动。这是旧候选的真实行为。该症状符合 Flash 键盘焦点仍指向已移除的按钮：焦点目标离开显示树后，按键不能沿原显示链到达 Stage。

本轮还未采集 `stage.focus` 的实际值，因此“焦点留在已移除按钮”仍是有运行现象和源码支撑的定位判断，不应写成已经观察到该对象引用。

## 源码修复

- `EpilogueView.closeModal()` 在移除 modal 子对象前保留 Stage，清理完按钮与面板后设置 `stage.focus=stage`。所有正常结束、已读跳过、选择、继续、失败重试、记录本关闭与 dispose 路径都经过这里。
- `ChapterButton` 关闭 Tab 聚焦；鼠标 click 回调前捕获 Stage，回调后在 `finally` 再把焦点交回 Stage。即使回调已经删除该按钮、打开另一模态或开始切图，也不依赖旧按钮的 `stage` 属性。
- 不清空 `EpilogueView.keys` 或 Esc 持键保护。键盘关闭面板时，原有“等抬键后才允许游戏接收重复按键”的防穿透语义保持。
- 背景透明输入屏障仍在；无需通过额外点击场景才能恢复按键。

## 只读诊断

`chapter/observer/Source.as` 的 sample 新增 `focus`：`type`、`name`、`onStage`、`sameStage`、`parentType`。只读取 `stage.focus` 及其显示树属性；不设置焦点、不派发事件、不模拟按键。焦点为空时记录 null。

## 下一轮实际回归

1. 鼠标跳过已读对白后不再点场景，直接 D/K/O/Esc，验证移动、跳跃、技能与暂停；observer 应显示 Stage 或有效在场显示对象。
2. 鼠标“继续旅程”“再次挑战”“关闭记录本”后立即操作角色；分别检查同场景恢复与切图恢复。
3. 鼠标从暂停进入记录本、用鼠标翻页/关闭，确认每个按钮路径后键盘仍可到 Stage。
4. 键盘 Enter/空格关闭对白时按住不放，仍不应把自动重复送入游戏；松开后正常移动/攻击。
5. 长按 Esc 打开暂停仍不会闪开闪关；鼠标继续后保持 Esc 按下也不应立即重开。

本轮只完成静态结构检查，**没有构建或启动修复后的候选，也没有声称问题已实测修复**。

## 胜利对白中的攻击特效遮挡（candidate5）

### 已观察到的问题

真实 candidate5 普通角色用 O 技能击败司灯后，立即出现胜利对白，巨大的蓝白斩击在画面中央持续停留；`chapter/evidence/private/021-candidate5-normal-warden-victory.png` 记录了对白与遮挡同屏的现象。截图未提供具体特效实例的类名，因此不能把某个 Fly 子类当作已确认根因。

源码路径可以解释该现象：`applyVictory()` 立即打开 `warden_defeat`，随后接 `devices`；`modalPause()` 同时暂停世界内播放中的 MovieClip 和游戏更新。玩家 `skin_W` 中的攻击图形以及脱离武器层、仍属于玩家的 Fly 会停留在当时画面。`ChapterEncounter.finish()` 已清除 Boss 危险物，不能为消退玩家特效而放开全部游戏更新。

### 本次最小修复

- 在 `applyVictory()` 开始或霍根第二阶段对白入口保存当前玩家 `skin_W` 及同一 world 内、`who === Main.player_1` 的 Fly 原始 `visible`，然后隐藏这些表现。角色本体、护甲、场景、Boss 均不在隐藏范围内。
- `dialogue()` / `notice()` 完成后先执行续接回调；若续接打开另一面板，则继续保留暂停及可见性快照。`warden_defeat → devices` 不再中途调用恢复，从而不让攻击图形在两段对白间重新出现。
- 真正恢复控制时，仅恢复仍在原 world 内的对象各自原始可见值；原本不可见的对象仍不可见。切图、回村及销毁直接清引用，不播放或重新插入旧世界对象。原生切图会重新创建玩家。
- 不删除 Fly，不调用 Fly.Dead，不修改技能帧、持续时间、runType、runArr、攻击命中状态或人物生命。原有 `paused`、世界时间轴暂停及伤害更新守卫继续承担暂停职责；`visible=false` 本身不是禁伤措施。
- 对白结束后攻击表现与动作会从原暂停点正常继续，可能短暂重新出现。这是保留原生动作状态的明确取舍，本修复解决的是整段对白期间持续遮挡，并没有宣称增加自然收招动画。

### 霍根第二阶段对白复用同一处理

主集成任务在 candidate5 真实触发霍根第二阶段时，也观察到 O 斩击冻结并遮挡“冠轮崩裂”演出。因此 `bossPhase()` 的 `scene == "regent" && encounter.phase == 2` 分支在打开 `regent_phase2` 前复用同一可逆隐藏流程；普通阶段变化不受影响。对白结束由已有 `resume()` 还原表现。

本补丁不修改 `ChapterEncounter`：进入 `transform` 时原有的 1.8 秒计时、暂停时不更新计时，以及恢复后的阶段转换流程均保留。待回归：用 O 触发第二阶段，检查对白期间玩家本体/Boss 可见且斩击不遮挡；结束对白后武器/特效恢复，变身继续按剩余计时完成，再进入第二阶段战斗。这里只完成源码改动与静态检查，未构建或运行修复后候选。
